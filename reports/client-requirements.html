User Stories

US-001
Dynamic Banners — Category-Tinted Rotating Hero
As a blog visitor, I want the blog listing hero to display rotating category banners with smooth transitions, so that the homepage feels alive and immediately communicates the breadth of content available.

Acceptance Criteria

  1. Given the blog listing page loads, when the hero banner renders, then it displays a full-width banner image with the category's accent gradient overlay and a kicker label (e.g., "Salesforce," "React & Web Dev").
  2. Given a banner is displayed, when 6 seconds elapse, then the banner transitions to the next category's banner with a fade or slide animation (duration 400ms, ease-out).
  3. Given the user hovers over the banner, when the mouse enters, then the auto-advance pauses; when the mouse leaves, then auto-advance resumes from where it left off.
  4. Given the user is on a reduced-motion preference, when the page loads, then the banner shows the current category without auto-advance (static display).
  5. Given the banner has no matching image for a category, when it renders, then it falls back to the category gradient (sky, emerald, amber, pink) with a subtle noise texture.
US-002
Site-Wide Motion System
As a reader, I want subtle micro-interactions on cards, links, and buttons, so that the site feels responsive and crafted without being distracting.

Acceptance Criteria

  1. Given a user moves their cursor over a PostCard, when the hover state activates, then the card lifts (-translate-y-1) with a category-tinted glow shadow and the banner image zooms (scale 1.03) over 300ms ease-out.
  2. Given a link is focused via keyboard (tab), when the focus-visible ring activates, then it displays a red (C8102E) 2px outline with 2px offset.
  3. Given a button is clicked, when the click occurs, then the button shows a brief scale-down (0.97) feedback animation (100ms) before returning to normal.
  4. Given the user has prefers-reduced-motion set to reduce, when any interactive element enters hover or focus, then all transforms, zooms, and lifts are suppressed (no motion, only color/state changes).
  5. Given a page loads, when the hero section becomes visible in the viewport, then it fades in from below (opacity 0 to 1, translate-y 8px to 0) over 300ms.
US-003
Blog Post Progress — Read/Unread Tracking
As a returning reader, I want blog post cards to show whether I have read each post, so that I can track my reading progress and pick up where I left off.

Acceptance Criteria

  1. Given a user visits the blog listing page while logged in, when PostCards render, then unread posts have a solid banner image and read posts have a dimmed overlay (opacity 0.6 on the banner).
  2. Given a user sees a dimmed (read) PostCard, when they click the card, then they navigate to the post detail page.
  3. Given a user is on the blog listing page, when they toggle the "Show unread only" filter, then only unread PostCards are displayed.
  4. Given a user has not logged in, when they visit the blog listing, then all PostCards render as unread (no dimming), and a subtle "Sign in to track reading progress" prompt appears near the filter toggle.
  5. Given a user reads a post, when they scroll past 75% of the article body, then the post is marked as read in Supabase and the listing card updates to dimmed state on next visit.
US-004
Learn Lesson Completion Tracking
As a learner, I want to mark individual lessons as complete and see my series progress bar update, so that I can track my certification or learning path progress.

Acceptance Criteria

  1. Given a user is viewing a lesson page, when they click "Mark complete," then the lesson is recorded in Supabase and the button changes to "Completed" with a check icon.
  2. Given a user has completed some lessons in a series, when they view the series page, then completed lessons display a checkmark badge and the PathCard progress bar reflects the updated percentage.
  3. Given a user unmarks a lesson (long-press or undo button within 10 seconds), when the action is confirmed, then the completion is removed from Supabase and the progress bar recalculates.
  4. Given a user is not logged in, when they click "Mark complete," then they are prompted to sign in (or create a free account) and redirected back to the lesson after auth.
  5. Given a series has N total lessons and M are completed, when the progress bar renders, then it displays "M/N completed" with a gradient fill from the series accent color.
US-005
Interactive Quiz Component
As a learner, I want to take quizzes embedded in lessons and see instant feedback, so that I can test my understanding before moving on.

Acceptance Criteria

  1. Given a lesson contains a quiz block, when the lesson page renders, then the quiz displays as a styled card with the question text and clickable option buttons.
  2. Given a user selects an option and clicks "Submit," when the submission is processed, then the correct answer is highlighted in green, incorrect answers in red, and the explanation text is revealed below.
  3. Given a user submits a quiz, when the result is shown, then the score (X/Y correct) displays with a color-coded status (green if 100%, amber if 50-99%, red if below 50%).
  4. Given a user has completed a quiz, when they revisit the same lesson, then their previous answers and score are displayed (they can retake for practice, but the original score is preserved).
  5. Given a series has quiz completion data, when the learner views the series overview, then the average quiz score for that series is displayed alongside the progress bar.
US-006
Supabase Data Model for User Progress
As a system, I need a Supabase schema to store user progress data (blog reads, lesson completions, quiz results), so that user progress persists across sessions and devices.

Acceptance Criteria

  1. Given the schema is deployed, when a user reads a post, then a record is upserted in the user_progress table with user_id, post_slug, read_at timestamp.
  2. Given a user completes a lesson, when the action is recorded, then a record is upserted with user_id, series_slug, lesson_slug, completed_at timestamp.
  3. Given a user takes a quiz, when the result is stored, then a record is upserted with user_id, series_slug, quiz_id, score, total_questions, taken_at timestamp.
  4. Given a user signs in via Supabase Auth, when their progress is queried, then all their records are returned in a single efficient query (indexed on user_id).
  5. Given Row Level Security (RLS) is enabled, when a user queries their data, then they can only read/modify their own records (never another user's).
US-007
Guest Mode Progress (Local Storage Fallback)
As a visitor who has not signed in, I want my reading progress to be tracked locally so I still get the dimmed-card experience, so that even without an account I can see what I have already read on this device.

Acceptance Criteria

  1. Given a user is not logged in, when they read a post, then the post slug is stored in localStorage and the card is dimmed on their device.
  2. Given a user later signs in, when they visit the blog listing, then their local progress is merged with their cloud progress (cloud takes precedence for matching slugs).
  3. Given a user clears their browser data, when they revisit the blog, then all cards render as unread (no stale local data).

Constraints

  1. No new npm dependencies. All motion uses existing Tailwind utility classes and CSS transitions. Supabase client is the only external dependency (already in .env.local).
  2. Must respect prefers-reduced-motion. All transforms, zooms, and lifts must be suppressed for users with reduced-motion preference. This is a hard requirement, not optional.
  3. Existing codebase integrity. Phase 1 code in src/ must not be reverted. This task adds features on top of the verified, building codebase.
  4. Build must pass. npm run build must exit 0 at all times. No TypeScript errors.
  5. Supabase project is pre-provisioned. zrggxfdyptiahskogwnn exists. Schema and RLS are in scope of this task; provisioning is a separate infra task (t_596af0ac).
  6. Server-side rendering compatibility. Progress tracking must work with Next.js App Router (SSR + client components). localStorage data is client-only; Supabase queries are client-side.
  7. No backend API routes for progress. All progress data goes directly to Supabase from the client via the anon key. No custom API layer.

Open Questions for Chris

Q1: Supabase Auth provider. The .env.local has Supabase credentials. Should users sign in with email magic link, Google OAuth, or both? This affects the auth flow design and the guest-mode merge strategy.
Q2: Quiz content format. Quizzes are embedded in MDX lessons. Should quiz data live in the MDX frontmatter (simple, author-editable) or in a separate Supabase table (more flexible, version-controlled)? This is an authoring workflow decision.
Q3: Progress retention period. Should old read/unread history be pruned? If a user has read 500 posts, do they all stay dimmed forever, or should there be a "last 30 days" window? This affects Supabase table size and query performance.
Q4: Quiz scoring weight. Does quiz performance affect the learning path recommendation? E.g., if a user scores below 50% on a quiz, should the system flag it to revisit? This is a product decision that affects the data model.
Q5: Kara's design discovery blocker. Kara's discovery task (t_7e4e4898) is blocked. What is the blocker? Is it a resource question, a scope clarification, or a technical constraint? This blocks the entire downstream pipeline (design -> arch -> infra -> impl).
