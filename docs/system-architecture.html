Tech Decisions & ADRs

IDTitleDecisionRationaleConsequences
ADR-001Supabase for progress persistenceSupabase (not custom API)Already configured in .env.local; SDK in node_modules; minimal infra overheadTables must be created; RLS policies needed for user-specific data
ADR-002localStorage fallback for guestslocalStorage with namespaced keysGuests have no auth identity; design mockups confirm localStorage-only for quizzesGuest data is device-bound; no sync across devices without auth
ADR-003Optimistic writes with fire-and-forgetPOST to API route, catch errors, fallback to localStorageUX must not block on network; design mockups show immediate toggle feedbackConflict resolution: localStorage pending writes synced when user authenticates
ADR-004Quiz data stays client-sidelocalStorage only for quiz attemptsPer direction brief §5.4: quiz attempts are ephemeral per sessionNo quiz analytics in Supabase; deferred enhancement if needed
ADR-005Single summary API endpointGET /api/progress/summary returns all dataReduces page-load round-trips from 3+ to 1Endpoint must handle large payloads; pagination if dataset grows
ADR-006Freeze content & data layersNo changes to content/, src/data/posts.ts, src/lib/sort.tsTask constraint: presentation layer onlyAll hooks read from existing data shapes; no schema changes to content
